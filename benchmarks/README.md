# Presentation benchmarks

Only synthetic or openly redistributable fixtures belong here. Private user documents are prohibited.

Suites: `academic-thesis`, `business-report`, `product-launch`, `data-dashboard`, and `reference-style`. Run `python scripts/verify-benchmarks.py` for the merge gate: it parses each automated family, extracts evidence, plans a deck, validates source-section links and required metric values, then enforces thresholds for planning quality, source coverage, the number of available composition families, accessibility, and the least-compatible supported delivery profile. Planned visual maturity has a lower threshold because no candidate has been rendered or selected yet; the project's quality checks assess selected layouts and real renders before final delivery. The reference-style family is generated: `reference-style/build_template.py` deterministically builds a synthetic enterprise template (invented brand, branded master, named cover/section/content/comparison/closing layouts). The gate checks that the analyzer learns its font and brand colour, that a planned deck fills every title and body placeholder, that cover/section/Q&A pages route to the matching master layouts, and that the master shapes, theme and layouts survive the fill.

The delivery profile score is a deterministic capability-rule check. A separate Office CI job generates PPTX files from all four automated fixture families and renders them through LibreOffice, checking page count and every planned slide title. This improves real-export coverage but does not replace desktop verification in PowerPoint or WPS.

Version v4 adds research-standard metrics computed in deterministic mode: PPTEval-style Content / Design / Coherence on a 1–5 scale (`app/evaluation/ppteval.py`, rule mapping of the quality metrics) and PaperQuiz-style information retention (`app/evaluation/quiz.py`: questions from numeric claims and key sentences of the source, answered from slide text only). The same evaluators accept LLM/VLM judges in the product and in `scripts/evaluate-deck.py --model/--vision-model`; model scores are not used as merge gates because they are not reproducible offline.

Version v5 adds two gates. **Faithfulness** (`app/evaluation/faithfulness.py`) searches the sources for every audience-visible claim and requires each number and nearby qualifier to be present in the best-matching chunk. **Gate perturbation** (`app/evaluation/perturbation.py`) injects known defects — an altered number, a fabricated claim, a duplicate title, a broken source reference, an emptied page and six render failures — and requires every targeted gate to fire on the targeted page (detection rate 1.0). This suite already found one gap: duplicate titles were not checked in decks shorter than 12 pages.

`manifest.json` defines the reproducible v5 thresholds. Add a synthetic fixture and its measurable requirements before adding an automated family to the manifest. The professional suite also checks layout contracts, narrative rhythm, brand consistency, accessibility, research governance, and cross-platform delivery. Detailed chart and numeric-claim regressions live in the presentation-engine and Python tests.

All benchmark content must remain synthetic or explicitly redistributable. Do not copy customer documents, API prompts, or model outputs that contain private data into this directory. Benchmark scores are deterministic regression signals, not a substitute for visual review in PowerPoint or WPS.
